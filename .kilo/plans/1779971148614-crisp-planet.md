# Plan: Determine Currently Running Components (Focus on Email Campaigns)

## Goal
Identify any active email **campaign** processes (e.g., scheduled send jobs, background workers) currently running in the **bemailsender** application.

## Steps
1. **Inspect entry point**
   - Read `package.json` for main script and npm start scripts.
   - Locate the primary entry file (e.g., `src/index.ts`).
2. **Search for campaign-related keywords**
   - Use `grep` to find terms such as `campaign`, `send`, `schedule`, `cron`, `agenda`, `bull`, `node-cron`, `setInterval`, `setTimeout` in source files.
   - Prioritize files under `src/jobs/`, `src/tasks/`, or any path containing “campaign”/“schedule”.
3. **Examine server initialization**
   - Open the entry file and imported modules that start an HTTP server or background workers.
   - Look for job scheduling libraries or explicit campaign dispatch calls.
4. **Check process managers**
   - Search for `pm2`, `forever`, or custom `child_process.spawn` usage that might run campaign workers.
5. **Review Docker/PM2 config**
   - Look for `Dockerfile`, `docker-compose.yml`, or `ecosystem.config.js` defining campaign-related services.
6. **Summarize findings**
   - List each active campaign job, its file location, and the mechanism that keeps it running.

## Deliverable
A concise report describing each running campaign component and how it is initiated.
